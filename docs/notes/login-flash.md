# Chrome login flash

## Current finding

The developer confirmed on 2026-11-10 that the full-page flash still occurred in Chrome with `vp dev`. On 2026-11-11 the login-to-Dashboard handoff was recorded frame by frame in Chrome Canary through a DevTools trace with screenshots, against `vp run dev:local` with the identity stub and fictional data, triggering the same marker and `location.replace` as `replaceSession`. The native cross-document transition ran every time (`pageswap` authorized, `pagereveal` with a transition, `ready` resolved, no rejection), so the flash was not a skipped transition or a blank document. It was what the transition painted:

- The `data-content-motion` gate paused every widget at its `backwards` opacity 0 until the overlay finished, so after the login panel faded the destination was an empty white surface for about 600ms of the 900ms morph, the brightest frames of the sequence, before the widgets appeared. That near-uniform white interval is the full-page flash.
- The white surface's captured images keep their own aspect ratios, so mid-morph the surface drew shorter than its group with cream showing beneath it, and the destination header sat over the cream rail before the surface reached it.

The fix removes the widget gate from `src/app.html` and `src/routes/+layout.svelte` (`onNavigate`) so widgets enter as they render, draws the white surface on its own view-transition group in `src/routes/motion.css` with the captured images hidden, and nests `workspace-content` inside that group with `view-transition-group: nearest` so content rides the surface's leading edge, clipped to it. Recordings afterwards show no empty-surface interval and a full-height surface throughout; Dashboard to Pipeline and Dashboard to login were also recorded without regression. Task 1.3's motion gate no longer exists, so a cancelled or rejected transition cannot leave widgets paused.

Fresh browser profiles also showed 150–300ms GPU stalls (Dawn pipeline compilation on a cold shader cache) that let the front-loaded morph jump forward; with a persistent profile frames were continuous, so that is a measurement artifact rather than the app. The dev-only variant toolbar appears one frame after the overlay is removed, which does not affect production. The developer's own Chrome check of the sign-in path is still the acceptance step for task 1.1.

## What has been tried

- Added the render-blocking `rel="expect"` link in `src/app.html:7`, pointing at the `workspace-ready` end marker at `src/app.html:70`, to defer first paint until the streamed shell is parsed. A read-only request confirmed that development HTML already includes the compiled CSS and cross-document opt-in; missing SSR CSS was not demonstrated.
- Moved the one-shot identity-navigation marker consumption into the parser-blocking head script in `src/app.html:35`. `pagereveal` selects native or fallback motion before first rendering; it no longer hides the whole workspace content while the marker is pending.
- Changed `src/routes/+layout.svelte:120` (`onNavigate`) to await `navigation.complete` and Svelte's DOM flush before taking the destination snapshot instead of using a timeout that can capture an intermediate view.
- Separated destination content into `workspace-content` at its final geometry instead of stretching it inside the expanding white surface. Removed the competing title, surface, and login-surface mount entrances.
- Centralized the route timeline in `src/routes/motion.css:1`: shell geometry and crossfade both take 900ms instead of the earlier 900ms geometry/400ms crossfade mismatch. Widgets wait for the native overlay to finish, then enter over 780ms with 110ms stagger. These values preserve the developer's preference for the slower shell; they are not evidence that the flash is fixed.
- Removed the pre-navigation login-form exit and its timed wait from `src/routes/login/+page.svelte:23` (`enterWorkspace`), keeping the source painted while the destination loads instead of deliberately introducing a blank interval.
- Changed `src/lib/shell/session-navigation.ts:28` (`replaceSession`) to authorize the destination on the outgoing document and separately mark the incoming document in sessionStorage. `src/routes/+layout.svelte:56` (`onPageSwap`) validates that exact same-origin destination instead of relying on storage the incoming document consumes. Explicit impersonation exit is now eligible; unrelated cross-document navigation still skips snapshots.
- Consumed outgoing transition promises in `onPageSwap`. Chrome reported `InvalidStateError: Transition was aborted because of invalid state. Page already revealed`; outgoing `ready` rejection can be normal when the old document becomes hidden. Suppressing an unhandled rejection is not a rendering fix, and that message alone does not identify the flash's cause.
- Changed `src/routes/+layout.svelte:27` (`verifySupportSession`) so a transient network or 5xx response does not replace the workspace as though it proved a different identity. Validated mismatches and access denial still leave the session; every server read/write remains authenticated.

## Evidence and limits

- The support-admin choice opened the realtor Dashboard, and the account menu was inspected with only Exit impersonation remaining. Settled-state captures do not show whether a one-frame flash occurred, whether the morph ran, or whether the stagger was perceptible.
- Exit impersonation was not exercised in the final browser pass: the wrong menu selector activated Log out. The browser session ended signed out. No business records were changed.
- An intermittent 500 appeared during HMR and rendered the new static recovery view; a subsequent fresh `/login` request returned 200. Its underlying cause was not identified. The earlier SSR URL-access failure is also not proven resolved outside HMR.
- The final `vp run check` reported zero errors and zero warnings, and `git diff --check` passed. No automated tests or production build ran. All implementation changes remain uncommitted, alongside earlier work; inspect the working tree before editing or committing.
- Graceful-error work already includes `src/routes/+error.svelte`, `src/error.html`, client/server error hooks, a route-keyed rendering boundary in the root layout, and a dashboard summary boundary. Session lookup failures negotiate HTML for document requests instead of always returning JSON. Mutation replay identity/payload mismatches now use `DataInvalid` instead of an unmapped plain error.

## Next diagnosis

Distinguish an intentional shell/content fade from a genuinely empty or incorrectly painted document. Inspect `pageswap` authorization, incoming `pagereveal`, `ViewTransition.ready` rejection reasons, first paint versus render-blocker release, and identity-triggered reloads. Compare login-to-workspace with the same-document form-to-choice transition; establish whether the flash happens before capture, during the snapshot overlay, or after it is removed.
